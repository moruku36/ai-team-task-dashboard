## Phase 1：必須受入試験

| ID | 試験 | 合格条件 |
|---|---|---|
| L01 | Windowsの対象ブラウザで起動 | localhostだけでログイン・看板・詳細を表示 |
| L02 | ネットワーク境界 | LAN/外部から到達せず、IPv4/IPv6/WSL含め広い待受なし |
| L03 | 非公開ファイル | data/DB/backup/config/log/隠しファイルをURLで取得できない |
| L04 | 初期資格情報・公開機能 | 初期ログインが使えず、公開リンク/webhook等が有効でない |
| L05 | 10件の架空タスク | 5列・候補/保留、本人待ち/環境待ち、優先度を識別できる |
| L06 | 次の一手と根拠 | 詳細から1操作で証跡に進め、未確認が明記される |
| L07 | スコープ別の完了 | 合成試験だけのカードを実接続完了と表示しない |
| L08 | 危険操作への非連動 | 列移動・コメント・approval表示変更で外部処理が起きない |
| L09 | 完了の整理 | 7日超を手動で閉じても検索/履歴から探せる |
| L10 | 再起動・復元 | 再起動後にデータが残り、別コピーへの復元で件数/ID/説明が一致 |
| L11 | キーボード・画面幅 | ドラッグ以外で状態変更でき、通常拡大でも主要操作が可能 |
| L12 | 単一更新者 | 誰が更新するか明示され、複数の自動更新経路が存在しない |

localhost限定のため、Phase 1では別スマホからローカル看板へ接続しない。狭いウィンドウによる確認はスマホ実機試験の代用と呼ばない。

## Phase 2で追加する試験

- A01：未ログイン/別ユーザーは直接API呼出しでも拒否。認証済み本人のreadはUI/APIとも許可される。
- A02：Windows電源を切り、スマホのモバイル回線から閲覧できる。Bでは最終snapshot時刻も一致。
- A03：秘密がHTML/JS/公開ファイル/ログに出ない。証跡先の共有範囲を拡大しない。
- A04：ログイン中断、戻る、再読み込み、セッション期限切れ、ログアウト後に情報が漏れない。
- A05：DB休止/通信断時にエラーと古い状態を明示し、空データや完了と誤認させない。
- A06：Bの二重importは1回分、古いrevisionは拒否、途中失敗は旧snapshot維持。
- A07：移行前後の件数・ID・重要項目・履歴を照合し、切戻しできる。
- A08：スマホで状態別の一覧、本人待ち、次の一手、証跡、鮮度が読める。

## Phase 1.5/3で追加する試験

イベント再送、作成応答消失、部分更新失敗、重複reference、古いfingerprint、同時更新、期限切れ資格情報、権限外プロジェクト、証跡commit不一致を検証する。単一writerでない場合は厳密なトランザクション/競合制御を導入するまで自動更新を許可しない。

## 実装バックログ（順序）

### 最初の小さな導入

1. **Windows構成を確認**：既存環境・対応版・ポート・保存先を確認。導入変更の承認を得る。
2. **Kanboardをローカルに準備**：安定版、最小依存、localhost限定、private設定。
3. **5列と記入例を設定**：架空10件、候補/保留、待ち理由タグ、短いdescription。
4. **安全性と復元を検証**：L01–L12。問題を修正してから実データ。
5. **少数の実タスクで試用**：単一更新者。読む負担が減ったか、情報が古くなる原因を確認。

### 効果が確認できてから

6. **単一API更新を検討**：転記負担が残る場合だけ、対象と許可された接続経路を決める。
7. **外出先の方式を選択**：A/B、既存ホスト、月額上限、情報の鮮度要件、用途を確認。
8. **認証付き閲覧を実装**：選んだ方式のみ。A01–A08に合格してから外部利用。
9. **複数AI更新を再評価**：実需要がある場合のみ別ADR。初版を待たせない。

工数・所要時間は実機確認前に確約しない。Kanboard標準導入と運用ルールを先に完成させ、閲覧UIや自動連携を同時に作り始めない。
