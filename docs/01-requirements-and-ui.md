## 目的・対象

長いチャット報告を読み返さず、「今動いていること」「止まっている理由」「自分が判断すべきこと」「次の一手」を1画面で確認できる。対象は本人1人とAIチーム。初期上限の目安は未完了100件、同時着手3件。タスク単位は1つの結果に結びつく大きさとする。

## 優先順位

### Phase 1で必要

- 標準Kanboardの看板と一覧、検索、担当表示、優先度、期限、証跡リンク。
- 各カードの先頭に「次の一手」。詳細を開けば更新時刻と未確認事項が分かる。
- 更新者は本人、または明示的に指定した1人。AI報告は更新者が確認して転記。
- 既存の重要作業と独立して導入。看板導入のために、進行中の仕事を止めない。
- Windows内で完結。外部送信なし、LAN・トンネル公開なし。

### 後続で必要

- 家・外出先のスマホから認証付きで閲覧。Windows停止中も最後の情報を見られる構成。
- 公開API経由の選択的更新、重複防止、更新履歴、データ移行。
- 複数AIの直接書込は必要性を確かめてから。初版の完成条件には含めない。

### 初版に入れない

会話全履歴の同期、AIの起動/停止、コマンド実行、購入/公開ボタン、予算執行、独自ログイン基盤、双方向オフライン同期、ガントチャート、通知の大量送信。

## 状態は5列、待ち理由はタグ

| 標準列 | 内部上の意味 | カードを置く条件 |
|---|---|---|
| 次にやる | ready | 目的と次の一手が決まっている |
| 作業中 | in_progress | 現に担当が進めている。目安3件まで |
| 待ち | blocked / waiting_owner | 理由、待ち相手、次に確認する条件を書く |
| 確認中 | verification | 成果物があり、受入条件の確認が残る |
| 完了 | done | 合意した今回の範囲の受入条件を満たした |

- `blocked` は環境・依存関係等、`waiting_owner` は本人の判断待ち。タグの文字で区別する。
- `backlog` と `hold` は別の「候補・保留」プロジェクトに置き、通常の看板に混ぜない。`hold` には再開条件を書く。
- 「完了」は直近7日だけ残す運用とし、以後は閉じる。閉じたタスクは検索可能で削除しない。初版では整理も手動。
- 待ち・保留は未完了。完了率をよく見せるために完了へ移さない。

## 表示する情報

標準カード面は `短いtitle / priority / 担当AIタグ / 待ち理由タグ`。AIの役割は `ai:review` 等のタグで表し、ログインして更新する本人とは分ける。Kanboard標準UIで独自フィールドがカード上に常時表示されるとは約束しない。次の一手・証跡・最終確認は説明先頭にまとめ、クリックで読む。

詳細は `next_action / owner_ai / evidence_url / current_commit / last_verified_at / 検証段階 / 承認待ちの説明`。初版は説明テンプレートで表現し、専用入力欄は作らない。

### デスクトップの情報配置（概念図）

```text
AIチーム   [未完了] [本人の判断待ち] [候補・保留] [完了を検索]
次にやる       作業中         待ち          確認中       完了
カードA        カードB        カードC       カードD      カードE
P2 / 設計AI    P1 / 実装AI    本人判断待ち   証跡あり      今週のみ
```

### スマホ

標準Kanboardは小画面で看板が使いにくい場合がある。まず一覧表示・絞り込み・タスク詳細で受入確認する。横スクロールだけで全体を把握させない。Phase 2Bの専用閲覧画面では状態タブと縦1列のカードを使い、最終同期時刻を常時表示する。

## 更新の鮮度

- `last_verified_at`：担当が根拠を見て状態を確認した時刻。単なる保存時刻と分ける。
- 初版：作業中が1営業日以上未確認なら更新者が「要再確認」タグを付ける。自動判定は後続。
- 待ち状態：`next_check_at` がある場合はその時刻を基準とする。無期限の待ちは理由を記載。
- スナップショット：画面に `source_updated_at / published_at` と「最新状態は未確認」を表示。通信失敗でタスクを完了扱いにしない。

出典：Kanboardの標準機能と小画面の注意点は [S3, S4, S8](08-sources.md)。列数・7日・確認周期は本設計の初期値で、製品既定値ではない。
