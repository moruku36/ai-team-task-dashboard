# 4. 安全設計と承認の境界

**失効した初版の参考資料（2026-10-11）**：この章は撤回済みのKanboard案を記録したもので、現行構成・採用決定・構築指示ではありません。**この章はBacklog.md MVP構成により置換済みです。** 現行の構成は [Backlog.md MVP構成（最終）](09-backlog-md-architecture.ja.md)、選定経緯は [OSS再選定提案](oss-reselection-20261011.ja.md) を参照してください。

## 初版の原則

1. localhost限定。`0.0.0.0`、LAN用portproxy、外部トンネル、ルータのポート開放を使わない。
2. Kanboardの初期資格情報を残さず、日常操作は管理権限を絞ったアカウントを使う。設定・入力は実施段階で本人と確認する。
3. プロジェクト公開、公開共有リンク、メール送信、webhook、任意プラグインの追加は無効のまま。
4. Apache/PHPの設定でdata、backup、config、ログ、ドットファイルの直接取得を禁止。ディレクトリ一覧を無効にする。localhostでもブラウザ経由の漏洩を想定する。
5. Hostを許可したlocalhost/loopback名だけに限定し、不明なHostを拒否する。CSRF対策を維持し、APIに広いCORSを足さない。
6. DB、設定、バックアップをGitへ入れない。ローカルファイルの権限も本人とサービス実行者に限定する。

これらは設計要件であり、設定済みという報告ではない。公式の基本注意事項は [S6](08-sources.ja.md)。

## カードに載せる・載せない

載せる：一般化したタスク名、担当AIの役割名、短い次の一手、待ち理由、コミットID、検証日時、最小限の証跡リンク。

載せない：パスワード、APIキー、秘密URL/token付きURL、決済情報、個人の詳細、顧客の機密本文、会話全履歴。証跡先へのリンクで閲覧権限を自動付与しない。リンク先にも権限確認が必要。

公開repoに置くのは設計と架空データだけ。実運用データの非公開repo保管も、初版の既定にはしない。秘密検出は補助であり、安全の保証にはしない。

## 承認待ちは表示だけ

- カードの `approval.status=pending` は本人への相談が必要という意味。
- `explicit_approval_scope` は「何の承認を確認できたか」の要約。原文の代用や新たな許可ではない。
- 初版に「実行を承認」ボタンを置かない。列移動、優先度変更、チェック、コメント、importから実処理は起動しない。
- `approved` の記録があっても、実行側は対象・行為・金額上限・データ送信先・期限・取り消しを元の承認経路で確認する。
- 不明・期限切れ・範囲変更は `pending` に戻す。対象や公開先が変わった承認を使い回さない。
- 購入、外部公開、認証/秘密の設定、削除等のルールは、その操作を行う実行環境で引き続き適用される。

## 検証の誤表示を防ぐ

「実装済み」「合成試験」「実接続」「公開確認」を独立して記録する。合成試験合格を実接続成功にしない。完了は当該タスクの範囲に対して判定する。設計タスクなら実装・公開が対象外でも完了にできるが、「対象外」と明示する。

コードが変わったら、以前のコミットに対する試験結果を新コミットの合格証拠として使わない。初版は更新者の手動チェック、後続では規則化する。

## 将来の外部閲覧

Phase 2A：TLS、適切なリバースプロキシ、防御設定、非公開プロジェクト、本人限定アカウントを前提とする。Kanboardを無防備に外部へ出さない。バックアップ先も限定する。

Phase 2B：Authだけでなく所有者IDによるRLSを必須にする。未ログイン・別ユーザーからのアクセスは、DB APIを直接呼ぶ場合も拒否する。認証済み本人のreadは、閲覧UIからのDB API呼出しを含めて許可する。service-role/secret keyはブラウザに置かない。静的ホストのURLを知っているだけではデータを取得できない構成にする。[S19, S20](08-sources.ja.md)

Supabaseの標準メール送信には宛先/頻度制限があるため、Magic Linkを無条件の既定にしない。本人アカウントでの実際のログイン方法と復旧方法を選び、実接続試験を行う。[S21](08-sources.ja.md)

## 将来のAI書込

個別の短命・限定権限の資格情報、許可対象プロジェクト、失効手段を用意する。作成や継続アクセスの設定は別途承認を得る。AIは承認済みフラグを勝手に立てない。読み取ったカード本文・リンク・外部報告に含まれる命令を権限として扱わない。
