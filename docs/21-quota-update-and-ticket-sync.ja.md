# 残量の手動更新・Argon表示・チケット差分の一回反映（運用メモ）

実データ・バックアップ・プラン・取り込み記録は、このリポジトリに入れません（リポジトリ外に保存）。

## 1. 残量の更新（`POST /api/quota`、オーナーのみ）
- 既存のオーナー認証・書き込みヘッダ・Origin検査の内側にあります。新しい認証や権限はありません。定期実行・自動転送は追加していません。
- 流れ: `node scripts/usage-upload-prepare.mjs <dashboard-usage.json> <出力先.json>` で、表示に必要な項目だけのファイルを作る → ログイン済みの画面の「残量データを取り込む」で選ぶ。
- 送られるのは許可リストの項目だけです（タイトル・HTTP詳細・内部応答・秘密・パス等は落とします）。
- 収集時刻・観測時刻はファイルの値のままです。サーバーの受信時刻（`usageUpdate.receivedAt`）は別に保存し、混ぜません。鮮度は表示のたびに現在時刻で判定します。
- 保存済みより古い収集時刻のファイル、収集時刻のないファイル、同じ要求IDで内容の違うものは 409 で拒否します。送ったプロバイダーだけが置き換わります。
- アカウント照合は `not_verified` のまま表示します（確認済みにはしません）。`mismatch` は値を出しません。
- 区別: 週次／5時間、取得失敗／未提供／無効（disabled）／0%、古い値（参考）。Argon（Gemini 4 Argon 週次）は共有枠と別に表示します。トークン数はこの取得ファイルに含まれないため、表示しません。
- **鮮度TTLは1時間（上限）です。** 2時間ごとの更新にすると、更新後の約1時間は「最新」、残りの約1時間は「古い（参考）」と表示されます。2時間運用へ切り替えるときに、TTLを延ばすか、この表示を受け入れるかを決めてください。

## 2. チケット差分の一回反映（`scripts/ticket-sync-plan.mjs`）
- `plan`: ローカルの `backlog/tasks`（と `archive/tasks`）、オーナーが保存した `GET /api/tasks` の写し、決定表から、適用プランを作ります（ネットワーク・書き込みなし）。プランは新規作成・状態のみ更新・保留・クラウド独自・archive・表示グループの差を分けて出します。
- 状態の更新は状態だけを変え、タイトル・担当者・本文・確認日時はクラウドの現在値を保ちます。表示グループは決定表で指定したカードだけ変えます。
- 本文が100000文字を超えるカードは切り捨てず保留します（APIの上限。64KiBはoperatorジョブ用の別の上限）。
- `verify`: プラン作成後にローカルのファイルが変わっていないかを、ハッシュで確認します（変わっていれば終了コード1）。
- 適用: ログイン済みの画面の「チケット差分を適用する」で、プランを選びます。作成から30分以内のものだけ受け付け、1件ずつ固定の要求ID・expectedVersionで送ります。競合（409）や失敗でそこで中止し、自動では戻しません（適用済みIDを表示します）。同じプランを再度送っても、重複しません。
- 元の `updated_date` は、プランの `privateRecords` に残ります（非公開）。API更新時刻とは別のものです。

## 3. ロールバックの注意
未設定（担当者空・グループ null）のカードや、Argon付きの残量を保存した後に、この変更より前のコードへ戻すと、`GET /api/tasks` が全体で 503 になります。復旧は、旧版へ戻さず、この変更を含む版を配信し直します。
