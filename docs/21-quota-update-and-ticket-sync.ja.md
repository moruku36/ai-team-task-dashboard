# 残量の手動更新・Argon表示・チケット差分の一回反映（運用メモ）

実データ・バックアップ・プラン・取り込み記録は、このリポジトリに入れません（リポジトリ外に保存）。

## 1. 残量の更新（`POST /api/quota`、オーナーのみ）
- 既存のオーナー認証・書き込みヘッダ・Origin検査の内側にあります。新しい認証や権限はありません。定期実行・自動転送は追加していません。
- 流れ: `node scripts/usage-upload-prepare.mjs <dashboard-usage.json> <出力先.json>` で、表示に必要な項目だけのファイルを作る → ログイン済みの画面の「残量データを取り込む」で選ぶ。
- **送信前に、ブラウザ側でも許可リストで絞ります**（タイトル・HTTP詳細・トークン・debug・内部応答・秘密・パス等は、通信本文に入りません）。サーバー側でも同じ許可リストで絞り直します（二重）。両者が一致することはテストで確認します。
- 保存前に、次を検査して失敗なら保存値を変えません（400）: 収集時刻の欠損、日時の形式不正、2020年より前、現在より5分を超える未来の収集・観測時刻。
- 収集時刻・観測時刻はファイルの値のままです。サーバーの受信時刻（`usageUpdate.receivedAt`）は別に保存し、混ぜません。鮮度は表示のたびに現在時刻で判定します。
- 競合（409）: 保存済みより古い収集時刻／**同じ収集時刻で内容が違う**／同じ要求IDで内容が違う。同じ内容の再送は無害な重複として扱います。要求IDは上限（50件）付きの受領履歴に残し、古いIDは忘れますが、時刻の規則で巻き戻しは防ぎます。送ったプロバイダーだけが置き換わります。
- アカウント照合は `not_verified` のまま表示します（確認済みにはしません）。`mismatch` は値を出しません。
- 区別: 週次／5時間、取得失敗／未提供／無効（disabled）／0%、古い値（参考）。Argon（Gemini 4 Argon 週次）は共有枠と別に表示します。トークン数はこの取得ファイルに含まれないため、表示しません。
- **鮮度TTLは1時間（上限）です。** 2時間ごとの更新にすると、更新後の約1時間は「最新」、残りの約1時間は「古い（参考）」と表示されます。2時間運用へ切り替えるときに、TTLを延ばすか、この表示を受け入れるかを決めてください。

## 2. チケット差分の一回反映（`scripts/ticket-sync-plan.mjs`）
- `plan`: ローカルの `backlog/tasks`（と `archive/tasks`）、オーナーが保存した `GET /api/tasks` の写し、決定表から、適用プランを作ります（ネットワーク・書き込みなし）。プランは新規作成・状態のみ更新・保留・クラウド独自・archive・表示グループの差を分けて出し、各操作に元のファイル名・SHA-256・更新時刻を結び付けます。
- 状態の更新は状態だけを変え、タイトル・担当者・本文・確認日時はクラウドの現在値を保ちます。表示グループは決定表で指定したカードだけ変えます。
- 本文が100000文字を超えるカードは切り捨てず保留します（APIの上限。64KiBはoperatorジョブ用の別の上限）。
- **適用は、ローカル検証と一体です。** 画面の「検証して適用する」は、プランに加えて、プランに書かれたローカルのタスクファイルを選ぶ必要があります。ブラウザはその内容のSHA-256を計算し、全件がプランの値と一致し、プラン作成後に更新されていない場合だけ、1件目を送ります。選んでいない・内容が違う・更新時刻が新しい・ファイル名／ハッシュ／更新時刻の結び付けがないプランは、何も送らずに拒否します。チェックボックスで代用することはしません。
  - **制約（隠しません）:** ブラウザはローカルを自動では見られません。検査できるのは、オーナーが選んだファイルの、選んだ時点の内容です。ライブのファイルの代わりに古いコピーを選んだ場合や、検査の後の変更は、ここでは検出できません（クラウド側は expectedVersion で守られます）。適用の直前に、続けて `verify` を実行してください。
- `verify`: プラン作成後にローカルのファイルが変わっていないかを、ハッシュで確認します（変わっていれば終了コード1）。
- 適用は作成から30分以内のプランだけ。1件ずつ固定の要求ID・expectedVersionで送り、競合（409）や失敗でそこで中止し、自動では戻しません（適用済みIDを表示します）。同じプランを再度送っても、重複しません。
- 元の `updated_date` は、プランの `privateRecords` に残ります（非公開）。API更新時刻とは別のものです。
